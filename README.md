# 地形沙盘 · 8 km 三维地形模型编辑

基于 **Three.js + Vite** 的单页三维地形应用：把 8 km × 8 km 的 DEM 高程图渲染成可自由浏览的地形
（高程位移、法线、环境光遮蔽、分层着色与等高线全部在 GPU 上计算，主线程不做任何像素循环），
并在同一份地形上做沙盘编辑：

- 导入多个 `.glb`，实时摆放 / 旋转 / 缩放 / 复制，按部件微调，给模型或部件打标签
- 在地形上点选放置水源，用 **GPU 浅水模拟**生成会流动、漫溢、蓄积的水面
- 用笔刷雕刻地形高程（**地形编辑**：升高 / 降低 / 平整 / 平滑），几何实时更新；可导出 16-bit 灰度 PNG 替换 DEM 源图
- 支持游览模式（隐藏 UI 的演示视角）与工程 JSON 导入导出
- 分块三档 LOD 卫星影像、高程分层着色、日间薄雾、相机碰撞、帧率自适应

仓库只有**一个前端**，就在仓库根目录：`npm run build` 的产物直接部署在站点根（GitHub Pages），
不再有独立子项目或子路径部署。以一份 8 km 的 DEM 为示例数据，换一份 DEM 即可复用于其他区域。

> 历史说明：模型编辑器曾作为独立子项目 `modeldesigner/` 单独部署在 `/modeldesigner/` 子路径下；
> 现已合并进仓库根项目，仓库只保留这一个前端，不再有 `/modeldesigner/` 部署路径。

## 快速开始

### 环境要求

| 依赖 | 版本 / 说明 |
| --- | --- |
| Node.js | ≥ 20.19（Vite 7 的要求），CI 使用 Node 22 |
| 浏览器 | 支持 WebGL2；集显即可运行（水体模拟需要浮点颜色缓冲，没有时自动退半浮点） |
| sharp | `devDependency`，仅离线资产管线使用，运行时不需要 |

### 安装与运行

```bash
npm install      # three / vite / sharp
npm run dev      # 开发服务器 http://127.0.0.1:5173
```

`npm run dev` 启动时会先检查 `public/data/` 的地形资产（见[自动资产守卫](#自动资产守卫)）：
缺失时自动执行完整资产管线（高度场 + 卫星瓦片）再启动，卫星瓦片生成约 20 秒（更慢的机器可能数分钟）。
想先单独把资产准备好，也可以显式执行：

```bash
npm run assets   # 完整资产管线（高度场 + 192 张卫星瓦片）
npm run dev
```

源数据放在 `resourses/`（或仓库根目录）后再执行 `npm run assets`，详见[数据准备](#数据准备)。

### 可用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | Vite 开发服务器（`127.0.0.1:5173`，端口被占用时自动递增）；启动前自动检测/补齐地形资产 |
| `npm run build` | 生产构建到 `dist/`（`base: './'`）；构建前后都会自动检查并补齐地形资产 |
| `npm run preview` | 预览构建产物（预览服务器没有模型资源写入接口） |
| `npm run assets` | 离线资产管线：DEM → `height.f16`，卫星影像 → 分块瓦片 |
| `npm run assets -- --height-only` | 只生成高度场，跳过卫星瓦片 |
| `npm run assets:check` | 只做资产自检，缺失时自动补齐（= `node scripts/ensure-assets.mjs`） |
| `npm run models:index` | 重建 `public/models/index.json`（静态托管时的资源清单） |
| `npm run models:sample` | 生成示例模型 `public/models/sample-tower.glb` |
| `npm run postbuild`（自动） | `npm run build` 之后自动执行，检查/补齐 `dist/data` |

## 自动资产守卫

`public/data/`（`height.f16` + `terrain.json` + `sat/*.jpg`）与 `dist/data/` 都是
`npm run assets` 生成的派生产物，已被 `.gitignore` 忽略 —— 干净检出后目录不存在。
此前这会导致两类问题：dev server 把 `GET /data/terrain.json` 回退成 `index.html`
（前端 `res.json()` 报 `Unexpected token '<'`），以及卫星瓦片缺失时地形只能降级成高程分层。
现在把「检测 + 缺失就自动生成」做成了默认行为：

**检测内容**

- `public/data/height.f16` 存在且非空
- `public/data/terrain.json` 可解析且 `width` / `height` 有效
- 当 `resourses/`（或仓库根目录）里存在卫星源图 `尚庄炉水库卫星影像64.png` 时，
  `public/data/sat/` 下必须齐全 **8×8×3 = 192 张**瓦片（`{cx}_{cz}_{2048|512|128}.jpg`）；
  没有卫星源图时只要求高度场（卫星影像是可选功能）

**触发时机**

- `npm run dev` / `npm run build` / `npm run preview` 启动时：`vite.config.js` 里的
  `scripts/vite-plugin-terrain-assets.mjs` 在 `configResolved`（早于 Vite 7 扫描 `publicDir`
  生成公共文件清单）检查 `public/data`，缺任一项就**同步执行** `node scripts/prepare-assets.mjs`
  （即完整的 `npm run assets` 管线），并打印中文进度；同一进程只尝试一次。
- 构建结束时：插件的 `closeBundle` 检查 `dist/data`，缺瓦片时先补 `public/data` 再同步进 `dist`；
  `package.json` 的 `postbuild`（`node scripts/ensure-assets.mjs --dist`）是同实现的第二道保险。

**失败策略**

生成失败（缺源图、缺 `sharp`、超时）**不会中断** dev / build：只打印可操作的中文提示，
页面按实际存在的资产自动降级（没有卫星瓦片 → 高程分层着色，功能不受影响）。

**手动修复**

```bash
node scripts/ensure-assets.mjs        # 检查 public/data，缺则自动跑全量资产管线
node scripts/ensure-assets.mjs --dist # 检查 dist/data，缺则补齐 public/data 后同步进 dist
```

> CI（`.github/workflows/deploy.yml`）不走自动守卫，而是显式 `npm run assets` 并校验
> `public/data/height.f16`、`terrain.json` 与 192 张卫星瓦片，缺一个就失败，
> 避免发布一个没有地形的站点。

## 功能总览

已实现：

- **地形渲染**：13 色标高程分层色带 + 矢量等高线；分块三档卫星瓦片 LOD（近景档
  2048²/1 km = 0.49 m/px，按块从源图重采样，细节上限由源图分辨率决定）；
  8×8 块 × 4 级几何细分；日间薄雾与地形边界雾化过渡
- **全局贴图开关**：一键切换地形卫星影像与模型自带贴图（`map`）
- **模型编辑**：多 `.glb` 导入（文件选择 / 拖拽 / 直接放资源文件夹）、资源库实时反映目录、
  选择、显示/隐藏、复制、删除、贴地、重命名；`TransformControls` 世界/局部变换 + 数值输入双向同步
- **部件级编辑**：部件树选择、部件局部变换与改名（都会写进工程）
- **标签**：模型级 / 部件级，先填名称创建（默认静态标注），可切换动态结构，场景内 CSS2D 跟随显示并按类型配色
- **水体模拟**：移植自 GPU 浅水模拟（4 个 ping-pong pass），模拟域自动覆盖全图，
  点选放置水源（最多 8 个，可连续放置 / 拖动 / 选中），水面菲涅尔反射、太阳高光、深度吸收、岸边与急流泡沫
- **地形编辑**：4 种 DEM 笔刷（升高 / 降低 / 平整 / 平滑），半径 10–600 m、强度 1–100%；
  笔刷落点指示圈跟随鼠标并贴着地形起伏（随垂直夸张、半径联动）；顶点着色器直接采样高度图，
  涂抹时几何逐帧更新（AO / 梯度约 180 ms 防抖重建）；撤销（Ctrl+Z）/ 恢复原始；
  编辑结果自动存 IndexedDB（刷新恢复），可导出 16-bit 灰度 PNG 替换 `resourses/heightmap64.png` 后重建资产
- **游览模式**：隐藏全部 UI 与场景标签的无 UI 演示视角，相机带惯性缓动
- **工程持久化**：`localStorage` 工程 + IndexedDB glb，刷新恢复；工程 JSON 导入导出
  （引用模式 / 内嵌 glb 模式，逐字段说明见 [docs/EXPORT-FORMAT.md](docs/EXPORT-FORMAT.md)）
- **相机**：统一手势（左键平移 / 中键旋转 / 右键旋转 + 缩放 / 滚轮朝光标缩放 / `W` `A` `S` `D` 水平平移 /
  `Q`·`E` 升降、`Shift` 加速 3.2× / `Ctrl` 缓动 0.25×）、碰撞开关（可关掉后自由穿行）
- **性能**：帧率自适应降分辨率，`FrameBudget` 抖动判据；FXAA 后处理替代 MSAA
- **GPU 信息**：启动时用双 `powerPreference` 探测实际绑定的 GPU（只展示，不做运行时切换），
  并监听 WebGL 上下文丢失 / 恢复

## 数据准备

### 源数据

| 文件 | 必需 | 格式 |
| --- | --- | --- |
| `resourses/heightmap64.png` | **是** | 1081 × 1081，16 bit 灰度 DEM（单通道） |
| `resourses/尚庄炉水库卫星影像64.png` | 否 | 3998 × 3920 卫星影像（PNG，约 38 MiB；含 alpha 时自动铺底。示例数据约 2.0 m/px，换上更高分辨率源图即可提升近景细节） |

两个文件都会在 `resourses/` 与仓库根目录两处查找。本仓库的两张源图都已在版本控制中跟踪，
因此干净检出后直接 `npm run dev` 即可自动生成完整资产（高度场 + 192 张卫星瓦片）；
如不需要卫星影像，可以只保留 DEM，页面会自动降级为高程分层着色。
地形编辑导出的 16-bit 灰度 PNG 与 `heightmap64.png` 同格式，重命名后放回 `resourses/` 即可替换 DEM 源图
（详见[地形编辑](#地形编辑)）。

### 资产管线行为

`npm run assets` 把两类源数据当作**各自独立的任务**：

- `heightmap64.png` 缺失 → 跳过高度场，打印提示，继续尝试卫星瓦片
- 卫星影像缺失 → 跳过瓦片生成并明确说明"运行时不提供卫星影像"
- 两者都缺 → 仍然以退出码 0 结束（只提示去放源数据），不制造无意义的失败
- `--height-only` → 显式只做高度场

产物写入 `public/data/`（该目录已加入 `.gitignore`，可由管线随时重建）：

```
public/data/
├── height.f16      # half-float 归一化高度，2.2 MB（1081²，GPU 零转换上传）
├── terrain.json    # 元数据：尺寸、地形边长、块数、高程区间
└── sat/            # 卫星瓦片（可选）
    └── {cx}_{cz}_{2048|512|128}.jpg   # 8×8 块 × 3 档 = 192 张
```

耗时参考（本机实测）：高度场约 2 秒；卫星瓦片把源图（3998 × 3920 ≈ 1570 万像素，PNG 约 38 MiB）
解码一次再逐块重采样，约 20 秒（一次解码而非逐块解码，否则要跑十几分钟），
总时长取决于源图尺寸与磁盘速度。

### 运行时降级

页面启动时会用一张远景瓦片（`sat/0_0_128.jpg`）探测卫星影像是否存在：

- 存在 → 创建瓦片调度器，「图形选项 → 贴图」可切换卫星影像，并出现「近景高清块数」
- 不存在 → 不创建调度器，**默认且只能展示高程分层地形**，贴图开关只影响模型贴图

因此没有卫星图是完全正常的运行状态，不是错误。

### `terrain.json` 字段

| 字段 | 说明 |
| --- | --- |
| `width` / `height` | 高度图像素尺寸 |
| `sizeMeters` | 地形实际边长（默认 8000 m） |
| `chunkCount` | 几何/瓦片分块数（默认 8，即每块 1 km） |
| `elevation.minMeters` / `maxMeters` | 高程区间，默认 55–310 m |
| `sourceRange` | 源图灰度极值与位深；地形编辑导出 16-bit 灰度 PNG 时用它把归一化高度映射回源灰度值 |

> 源图不含地理元数据，高程区间是按该区域地形的估计值。可直接改 `terrain.json`；
> 垂直夸张只影响观感，不影响拾取、贴地与水源高程的换算。

## 界面与操作

### 顶栏与布局

顶栏有六项：

| 顶栏 | 内容 |
| --- | --- |
| **项目管理 ▾** | 导出工程 / 导入工程 / 清空场景 |
| **模型编辑** | 左「场景资源」（资源库 + 导入 glb + 场景模型）｜右「模型编辑」（部件树 / 名称 / 变换 / 标签 / 贴地 / 删除） |
| **水体编辑** | 左「水体模拟」（＋水源 / 清空 + 水源列表）｜右「水体模拟」（模拟参数 / 选中水源 / 外观 / 保存 + 状态） |
| **地形编辑** | 左「地形编辑」（4 种笔刷 / 半径 / 强度 / 撤销 / 恢复原始 + 落点指示圈与状态）｜右「地形与导出」（尺寸 / 导出格式 / 源灰度范围 / 已修改点 / 导出 16-bit 灰度 PNG） |
| **图形选项 ▾** | 贴图、碰撞、水面、标签显示开关；薄雾强度 / 垂直夸张 / 分层数 / 等高线滑杆；近景高清块数下拉；当前 GPU 名称 |
| **游览** | 隐藏全部面板进入无 UI 游览模式（相机带惯性缓动），`Esc` 或右下角按钮退出 |

「模型编辑」「水体编辑」「地形编辑」三种模式**互斥**，且共用同一套两列栅格（左 340 px / 右 460 px）：
顶栏与左右两栏的位置、宽度在切换模式时完全不变，只有面板内容替换。上次停在哪个模式会记住，
刷新后恢复（地形编辑模式下左键落在地形上时用于涂抹，其余手势仍是相机操作）。顶栏右侧状态区每 0.25 s 刷新一次运行状态：
`FPS（帧时间）· 三角面数 · 渲染分辨率@像素比 · 场景实例数 · 资源数 · 自动保存状态`。

### 图形选项

「图形选项 ▾」集中管理视图状态（全部存 `localStorage`，刷新后保持）：

| 控件 | 范围 / 默认 | 说明 |
| --- | --- | --- |
| 贴图 | 开 / 关（默认开） | 开＝地形铺卫星瓦片（若有瓦片）+ 模型显示 glb 自带贴图；关＝地形回高程分层、模型回纯色 PBR |
| 碰撞 | 开 / 关（默认开） | 相机是否被地形与地形边界挡住 |
| 水面 | 开 / 关（默认开） | 水体总开关；关闭后不渲染水面、也不推进模拟 |
| 标签显示 | 开 / 关（默认开） | 场景内 CSS2D 标签是否显示 |
| 薄雾强度 | 0–3×（默认 1.0×） | 地形雾 `uFogDensity`、水面（同一 uniform）、模型 `scene.fog` 一起调 |
| 垂直夸张 | 1–8×（默认 1.8×） | 只作用于梯度与位移，光照法线始终自洽；水面高度同步 |
| 分层数 | 6–48（默认 48） | 高程色带的量化层数 |
| 等高线 | 0–100%（默认 100%） | 线宽随屏幕导数自适应，任何距离约 1 px |
| 近景高清块数 | 3 / 6 / 9（默认 3） | 仅卫星模式；同时驻留的 2048² 瓦片上限 |
| GPU 名称 | 只读信息 | 菜单底部显示当前 WebGL 上下文**实际**绑定的设备；不做运行时切换（见[渲染设备](#7-渲染设备不做运行时切换)） |

### 游览模式

顶栏「游览」用于演示与截图：

- 隐藏工具栏、左右面板、底部提示与场景标签（以及水体模式的**水源小球 / 半径圆环**、地形编辑的**笔刷指示圈**），
  只留右下角「退出游览 · Esc」
- 沿用与编辑模式**完全相同**的相机手势（左键平移 / 中键旋转 / 右键旋转 + 缩放 / 滚轮 / `W` `A` `S` `D` 平移 /
  `Q`·`E` 升降、`Shift` 加速 / `Ctrl` 缓动）；相机开启**惯性**：起步按指数缓动加速，松开按键后继续滑行一段再停，旋转阻尼也更柔
- 与编辑互斥：进入时会先取消正在进行的选点；`Esc` 或点右下角按钮退出，UI、水源标记、笔刷指示圈与相机手感恢复原状

### 视角操作

所有模式（模型编辑 / 水体编辑 / 地形编辑 / 游览）使用同一套相机手势：

| 操作 | 功能 |
| --- | --- |
| 左键拖动 | **平移**（相机与观察点一起平移；地形编辑模式下左键落在地形上时优先涂抹，编辑期间相机让位） |
| 中键拖动 | 绕观察中心**旋转** |
| 右键拖动 | 横向 = 绕观察中心旋转；纵向 = **缩放**（向上拖拉近 / 放大，向下拖拉远 / 缩小） |
| 滚轮 | 朝光标缩放（上滚放大、下滚缩小；范围 60 m – 26 km） |
| `W` `A` `S` `D` | 水平前后左右移动（速度随观察距离自适应） |
| `Q` / `E` | 降低 / 抬高视角高度（相机与观察点一起升降） |
| `Shift` | 加速移动 3.2×（作用于 `W` `A` `S` `D` / `Q` `E`） |
| `Ctrl`（macOS 也认 `⌘`） | 缓动移动 0.25×（用于精确构图） |

> `Shift` / `Ctrl` 是键盘移动的加速 / 缓动修饰键，**不改变鼠标语义**：按住它们左键拖动仍是平移，不会变成旋转。
> 模型 gizmo 拖动、水体水源拖动优先于相机手势；模型编辑里轻点左键仍然是选中模型（拖动才是平移）。

### 相机碰撞

「图形选项 → 碰撞」控制相机是否被地形挡住：

- **开**（默认）：不会钻进地形（按最小离地高度贴地），也不会飞出地形方形边界
- **关**：自由穿行 —— 可以钻到地形以下、飞出土地方形范围，方便检查地下/边界效果

状态存在 `localStorage`，刷新后保持。碰撞对平移 / 旋转 / 缩放都生效，与用哪种手势移动相机无关。

## 模型编辑

### 模型从哪来

三种方式，最终都会汇入同一个**资源文件夹** `public/models/`：

| 方式 | 行为 |
| --- | --- |
| 把 `.glb` 直接放进 `public/models/` | 刷新页面即出现在左侧「资源库」（dev 下是实时目录扫描） |
| 网页「导入 glb 模型」或把文件拖进窗口 | dev server 会把它**写回 `public/models/`**（`POST /__models/upload`），同时放进场景 |
| 静态托管（`npm run build` 产物）导入 | 没有写盘能力，glb 暂存到浏览器 IndexedDB，界面上可「⇥ 移入 public/models」或「⭳ 下载文件」后自行放入 |

左侧「资源库」**始终显示资源文件夹里的内容**，其次是浏览器里暂存的资源（标注为「本地」）。
dev 下的资源接口是 `/__models/list|upload|delete`；构建时插件会自动生成 `public/models/index.json`
清单，静态托管时前端靠它列资源（也可手动 `npm run models:index`）。

试试生成一个示例模型（底座 + 塔身 + 转臂，便于演示部件标签）：

```bash
npm run models:sample     # 生成 public/models/sample-tower.glb
```

### 编辑

检查器自上而下是：**部件 → 名称 → 变换 → 标签 → 模型**。
所有编辑都跟随「当前选择」——而选择只有两种来源：

| 操作 | 功能 |
| --- | --- |
| 在**部件栏**点「整个模型」/ 某个部件 | 决定下面「名称 / 变换 / 标签」作用于谁 |
| 左键单击场景里的物体 | 只选中**整个模型**（不会选中部件）；左键**拖动**是相机平移 |
| `1` / `2` / `3` | 切换 gizmo：移动 / 旋转 / 缩放 |
| 拖 gizmo | 实时变换当前选择，检查器的 P/R/S 数值同步刷新（拖动期间自动禁用相机，避免同时带动视角） |
| 检查器数值框 | 精确输入位置（米）/ 旋转（度）/ 缩放（倍率）；每轴带 X/Y/Z 标记，颜色与 gizmo 轴一致（X 红 / Y 绿 / Z 蓝） |

| 「贴地」 | 把模型包围盒最低点落回地表（作用于整个模型） |
| 「删除模型」 / `Delete` | 删除整个模型 |
| `Ctrl+D` / 列表里的 ⧉ | 深拷贝一份（含标签与部件变换），沿 X/Z 各偏移 60 m 放置 |
| `Esc` | 取消选择 |

> 没有「编辑模型 / 编辑部件」这类开关：点部件栏里的谁，就编辑谁。

### 标签

标签挂在**当前选择**上，列表也只显示当前范围的标签：

1. 在部件栏点「整个模型」或某个部件
2. 在名称框里填**标签名称**（留空则用模型名 / 部件名），点「+ 添加到整个模型」（或「+ 添加到该部件」）
3. 新标签**默认为「静态标注」**（琥珀色胶囊），需要时在标签卡上点

4. 名字和类型都可以随时改；类型只是给这个标签定性，不附带别的作用

> 也就是说：**创建时只管名字，默认静态标注，类型随时可改**；标签只属于它挂的那个对象。

## 水体模拟

水体使用 **GPU 浅水模拟**（three.js 适配版），旧的「水面区域 / 流动水」模块已整体删除。

实现位于 `src/water/`：`fluidWater.js`（模拟主类：模拟域 / 水源 / 参数 / 序列化）、
`waterShaders.js`（4 个 ping-pong pass + 水面网格着色）、`waterTextures.js`（程序化法线 / 泡沫纹理）、
`waterState.js`（schema 默认值与归一化，工程与运行时共用）。

### 模拟域：自动覆盖整个地形

- 模拟域**自动覆盖整个 8 km 地形**（`heightField.sizeMeters`），高程直接取现有的
  `heightField.texture` —— 与地形顶点着色器用的是同一份 DEM（R16F 归一化高程），
  所以**没有「创建高度图 / 手动调模拟范围」这一步**
- 直接在地形上点选放置水源即可开始注水，水面自己按地形起伏扩散、漫溢、蓄积
- 模拟在 256–1024 的 GPU 纹理上跑；渲染用的水面网格是覆盖全域的一张平面网格，
  顶点按模拟水位位移，两者解耦

### 水体编辑模式

顶栏「水体编辑」切到水体模式（与「模型编辑」互斥，共用同一套两列栅格）。左右面板与模型模式对称：

| 位置 | 内容 |
| --- | --- |
| 左「水体模拟」 | ＋水源 / 清空 + 水源列表（名称、地面高程、半径、启用、删除） |
| 右「水体模拟」 | 模拟参数（模拟速度 / 每次注水量 / 模拟精度 / 暂停 / 重置）→ 选中水源（名称 / 地面高程（只读）/ 水源半径 / 目标水面高程 / 启用 / 删除）→ 外观（太阳高光 / 波纹强度 / 水体清澈度）→ 保存 + 状态 |

放置与编辑：

1. 点「＋水源」进入放置模式：画布变十字准星，顶部出现放置提示
2. 在地形上单击放置水源，可**连续放置**（最多 8 个）；左键单击才放置，左键拖动仍是相机平移，不会误放
3. `Esc`、再点一次「＋水源」或右面板「结束放置」退出放置模式
4. 水源在场景里显示为**青色小球 + 贴地半径圆环 + CSS2D 名称序号**（如「1 · 水源 1」）；
   小球可按住水平拖动改位置（松开才提交），点击小球选中（选中后小球变白、圆环变黄）
5. 水源标记只在水体编辑模式显示；切回模型模式会自动隐藏并结束放置

### 模拟怎么跑（4 个 ping-pong pass）

每个**子步**依次跑 4 个全屏 pass：

| pass | 写什么 | 读什么 |
| --- | --- | --- |
| A | 地形高度 + 水深（含水源注水） | C、D |
| B | 4 向流出量（第 1 段） | A、D |
| C | 地形高度 + 水深（第 2 段） | A、B |
| D | 4 向流出量（第 2 段） | C、B |

- 4 个模拟缓冲都是浮点颜色纹理（正常为 RGBA32F；GPU 不支持浮点颜色缓冲时自动退到半浮点，精度略低但可用）
- 水源注水按固定节拍（每 2 个子步注入一次），注到目标水位就停
- 每帧的子步数由「模拟速度」控制：0.1–4 倍，1× = 60 Hz 下每帧 1 个子步；单帧最多推进 4 步，
  掉帧后不会一次补跑太多
- **模拟域边界当作封闭的墙**：朝地形外侧的流量记 0，邻居采样也不跨出边界 —— 水既不会从边界漏光，
  也不会因为边界重复计数而"凭空变多"
- **全局水位上限** = 所有**启用**且设置了目标水位的水源里的**最高目标水位**；只要有任一启用水源
  是「不限制」，就**没有**上限。超出上限的水被直接排掉（相当于溢洪道），
  所以多个水源也不会把整张地图无限灌高

### 面板参数

**模拟参数**：

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 模拟速度 | 0.1–4× | 1× | 1× = 60 Hz 下每帧 1 个子步 |
| 每次注水量 | 1–300 米 | 15 米 | 每个水源每次注水按这个水深注入 |
| 模拟精度 | 256 / 512 / 768 / 1024 | 768 | 模拟网格边长；切换会重建模拟缓冲，水位归零重新模拟 |
| 暂停 / 继续 | — | 运行中 | 暂停时不再推进模拟，但仍显示当前水面 |
| 重置模拟 | — | — | 水位与流量全部清零，从干地重新开始 |

**选中水源**：

| 参数 | 范围 / 默认 | 说明 |
| --- | --- | --- |
| 名称 | 默认「水源 N」 | 也显示在场景的 CSS2D 名称里 |
| 地面高程 | 只读 | 按水源位置自动采样；新水源的目标水位默认 = 该值 + 10 m |
| 水源半径 | 20–2000 米（默认 150） | 注水范围；场景圆环按此半径贴地绘制 |
| 目标水面高程 | 米；0 或留空 = 不限制 | 该水源注到这一高程就停；新水源默认 = 地面 + 10 m |
| 启用 | 默认开 | 停用的水源不注水，也不参与全局水位上限 |
| 删除 | — | 只删这个水源，已经流进模拟里的水会留下 |

**外观**：

| 参数 | 范围 | 默认 |
| --- | --- | --- |
| 太阳高光 | 0–3 | 1.0 |
| 波纹强度 | 0–2 | 1.0 |
| 水体清澈度 | 0–1 | 0.62（0 浑浊、1 通透） |

> 最多 **8 个水源**；「清空」删除全部水源；「保存」立即写入本地工程。
> 面板底部状态行显示 `步数 N · 水源 M`（暂停时追加「已暂停」）；湿格数与最深值来自
> `debugStats()` 的 GPU 读回，供调试/自动化使用。

### 水面渲染

一张覆盖全域的网格（默认 **512×512 段**）按模拟水位在顶点着色器里位移；片元里：

- 用模拟水位求几何法线，再叠两层**程序化法线贴图**（可平铺、带 mipmap + 各向异性过滤，
  沿净流速方向平流）—— 近处细碎、远处不闪
- **Schlick 菲涅尔**：正视看水体色，掠视几乎全是天空反射；反射色与天空着色器同色
- **太阳高光**：锐利太阳镜面 + 较宽泛光 + 掠射角细碎波光（由「太阳高光」控制）
- **深度吸收（Beer-Lambert 近似）**：浅水透出水下地形色，深水接近不透明；
  「水体清澈度」控制吸收强弱
- **泡沫**：岸边拍岸细碎泡沫 + 急流白浪（由净流速与水深驱动）
- 与地形**完全一致的日间薄雾**和地形边界淡出：水面在边界处淡出到透明，不会露出方形硬边

「图形选项 → 水面：开 / 关」是水体总开关，关闭后不渲染、也不推进模拟。

### 精度与性能

- 模拟分辨率决定模拟网格的物理大小：8 km ÷ 256 ≈ 31 m/格，512 ≈ 15.6 m/格，
  768 ≈ 10.4 m/格，1024 ≈ 7.8 m/格
- 768 时 4 个 RGBA32F 模拟缓冲各约 9 MB（另有一张同分辨率的合成纹理）；
  256/512 更快更省显存，1024 最细但 GPU 开销最大
- 需要 **WebGL2 + 浮点颜色缓冲**（`EXT_color_buffer_float`）；没有时自动退半浮点

### 持久化

- 水体数据写入工程 JSON 的 `water` 字段：`{ enabled, sim, visual, sources[] }`
  （逐字段说明见 [docs/EXPORT-FORMAT.md](docs/EXPORT-FORMAT.md)）
- 水源与参数变化走工程自动保存（400 ms 防抖），也可点面板「保存」立即落盘
- 恢复工程时按保存的**水源与参数重新开始模拟**：不保存当前水位，水面从干地重新注水
- 旧工程的 `areas` / `flows` **不迁移**，归一化后 `sources` 为空

## 地形编辑

「地形编辑」是第三个编辑模式（与「模型编辑」「水体编辑」互斥，共用同一套两列栅格）：
用笔刷直接改 DEM 高程，地形几何实时更新；要长期保存或分享地形形状，导出 16-bit 灰度 PNG。

### 面板

| 位置 | 内容 |
| --- | --- |
| 左「地形编辑」 | 4 个笔刷工具（升高 / 降低 / 平整 / 平滑）；笔刷半径 / 强度滑杆；撤销（Ctrl+Z）/ 恢复原始；状态行与用法提示（含鼠标处的落点指示圈） |
| 右「地形与导出」 | 尺寸（当前示例 1081×1081）、导出格式（16 bit 灰度 PNG）、源灰度范围、已修改点；「导出灰度图（16-bit PNG）」；源图替换说明 |

### 笔刷工具

| 工具 | 行为 |
| --- | --- |
| 升高 | 按住左键在地形上抬升（半径内按平滑钟形衰减叠加） |
| 降低 | 与升高相反，向下压 |
| 平整 | 把笔画经过的高度向**落笔点**的地面高程拉平（适合整平台地） |
| 平滑 | 对笔刷区域做可分离盒式模糊（模糊半径约为笔刷半径的 45%，2–14 像素），再把高度向模糊值收敛；强度 100% 时效果明显，可快速抹平锯齿 / 噪点 / 小起伏 |

用法：在地形编辑模式下**按住左键涂抹**即可连续修改（笔刷落点指示圈跟随鼠标、贴着地形起伏）；
中键拖动旋转、右键拖动左右旋转 / 上下缩放、滚轮缩放、`W` `A` `S` `D` 平移、`Q` / `E` 升降（`Shift` 加速 / `Ctrl` 缓动）；
`Esc` 结束当前笔画。涂抹期间相机与模型拾取暂时让位，松开后恢复。

### 笔刷参数

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 半径 | 10–600 m | 80 m | 笔刷覆盖范围，按当前地形分辨率换算成 DEM 像素 |
| 强度 | 1–100% | 30% | 每帧修改量；100% 约 1.4 秒满量程（60 fps 下每帧约 1.2%） |

### 实时渲染（不重建几何）

- 地形顶点着色器直接采样**原始高度图** `uHeight`（`heightField.texture`，R16F）；笔刷修改 CPU
  归一化高度与 half 位模式并置 `texture.needsUpdate` —— **下一帧几何就按新高度渲染**，
  不需要重建地形分块网格。
- 着色用的 AO / 梯度查询纹理有延迟：涂抹过程中约 **180 ms** 重建一次；笔画结束 / 撤销 /
  恢复原始时立即重建。所以拖动时高度立刻变，光影细节稍后跟上。
- 水面（`FluidWater` 读同一份高度纹理）、模型贴地与水源高程都会按新地表计算。

### 笔刷落点指示圈

地形编辑模式会在鼠标下方显示一圈浅蓝色圆环，提示这次笔刷会落在哪、范围多大：

- **跟随落点**：圆环跟随鼠标在地形上的实际交点（不是屏幕位置），在地形范围外时隐藏；
- **贴地形起伏**：圆环逐顶点采样高度（128 段 / 256 顶点），再乘垂直夸张并抬升 1.5 m，
  所以山地、坡面、谷地上圆环会贴着地表起伏而不是悬空或穿地；
- **与半径联动**：拖动「半径」滑杆时圆环立即按新的米数重画（内外圈半径各为 `半径 ∓ 1.4 m`）；
- **相机移动时仍贴地**：滚轮 / `W` `A` `S` `D` / 拖动惯性让相机移动后，会约每 70 ms 用光标位置
  重新拾取地形，圆环保持在光标下的地表上；
- **隐藏时机**：鼠标移出画布、切到其他模式、进入游览模式时自动隐藏。

### 撤销与恢复原始

- **撤销**（`Ctrl+Z` 或面板按钮）：每次笔画开始前保存整幅归一化高度快照，最多保留 8 步。
- **恢复原始**：把高度逐字节还原成加载时的原始 half 位模式，并清空撤销记录。
- 面板与状态行显示「未编辑 / 已编辑」「N 次编辑」「N 个点」等信息。

### 持久化（浏览器 IndexedDB）

- 每次编辑后约 900 ms 自动保存到 IndexedDB（库 `terrain-modeldesigner`、store `world`、
  键 `terrain-edit-v1`）；刷新页面时在构建查询纹理**之前**恢复，所以高程与光照都是编辑后的状态。
- 地形编辑**不属于工程 JSON**：导入工程 / 清空场景都不会改变地形；换浏览器或清浏览器缓存会丢失。
- 想长期保存或换机使用，请导出灰度图并重建资产（见下）。

### 导出 16-bit 灰度 PNG（替换 DEM 源图）

- 尺寸 1081×1081（当前示例），16 bit 灰度、单通道，与 `resourses/heightmap64.png` 同格式；
  行序为「北在上」（与 height.f16 / 卫星瓦片一致），灰度值 =
  `round(sourceRange.min + normalized × (sourceRange.max − sourceRange.min))`；
  `sourceRange` 取自 `terrain.json`（当前为 12596–53742）。
- 导出文件名为 `heightmap-edited-<时间戳>.png`；把它重命名为 `heightmap64.png` 放进
  `resourses/`，再执行 `npm run assets`，即可重建 `public/data/height.f16` 与 192 张卫星瓦片，
  之后基线地形就是编辑后的 DEM。
- 编码在浏览器端完成（`CompressionStream('deflate')`，零依赖、不经过 canvas）；
  Node 端往返测试：`node tests/height-png.test.mjs`。

## 工程与持久化

- **自动保存**：任何编辑（变换、改名、增删模型/标签、增删水源、调水体参数）400 ms 后写入
  浏览器 `localStorage`（工程结构与 glb 分离；水源与水体参数也在工程里）
- **刷新恢复**：glb 从 `public/models/` 或 IndexedDB 重新读取，变换与标签全部还原；
  水体按保存的水源与模拟参数重新开始注水（不保存当前水位）
- **导出工程**：`项目管理 → 导出工程` →
  - 确定 = **内嵌 glb**（单文件，可跨机器，体积大）
  - 取消 = **只导出引用**（依赖 `public/models/` 里的文件）
- **导入工程**：会替换当前场景；内嵌模式会自动把 glb 写回资源文件夹（dev）或暂存到浏览器（静态托管）
- **清空场景**：只清实例、水体与本地工程，不动资源文件夹
- **地形编辑不属于工程 JSON**：高度改动单独存 IndexedDB 世界状态，导入 / 清空工程都不会改变地形；
  要保存或分享地形形状，用「地形与导出 → 导出灰度图」把 PNG 放回 `resourses/` 后重建资产

导出 JSON 的逐字段说明（坐标约定、单位、索引路径、标签结构、水体状态）见

## 技术文档

### 架构与数据流

```
heightmap64.png ──(Node: 16bit 解码 + half 归一化)──► public/data/height.f16 (2.2 MB)
                                                          │
                                                DataTexture(R16F)  零转换上传
                                                          │
                              ┌───────────────────────────┴───────────────────────────┐
                     离屏 pass（gpuLookup.js）                            顶点着色器
          R=高度 G=AO B=∂h/∂x A=∂h/∂z  (RGBA16F 查询纹理)        高度 = 纹理采样位移
                              │                                                       │
                     片元着色器：法线 / 光照 / 分层 / 等高线 / 日间薄雾 ◄──────────────┘
```

- 几何只存平面坐标（x/z + uv），高程全部由顶点着色器从高度图 `uHeight` 解析（地形编辑时重新上传）
- 运行时只有静态资源，没有服务端逻辑；`build` 产物可放在任意静态托管
- 水体模拟直接复用同一份 `heightField.texture`，渲染时与地形共用雾 / 天空 / 太阳 uniform；
  地形编辑改变高度图后，水面与模型贴地会自动按新地表计算

### 1. 高程分层着色（算出来的，不是贴图）

- 色带是 512×1 的 LUT 纹理，色标定义在 `src/terrain/palette.js`
- 分层用 `floor(h * bands)` 量化，层内保留少量连续渐变，避免色阶把起伏吃掉；分层数可调 6–48
- **等高线用 `fwidth(h * bands)` 换算线宽**：线宽随屏幕导数自适应，任何距离、任何倾角都保持约 1 px，不会闪成麻点

### 2. 消除"像素方块感"

方块感通常来自五处，这里逐一消除：

| 来源 | 处理 |
| --- | --- |
| 8 bit 量化台阶 | 源图 16 bit 直接转 half-float 上传，不经 canvas（canvas 只能给 8 bit） |
| 最近邻 / 双线性采样的菱格 | 片元与顶点都用 4×4 = 16 tap 的 **Catmull-Rom 双三次采样** |
| 低面数网格的平面着色 | 法线不来自几何，而是由高度场梯度矢量解析：`n = normalize(-gx·k, 1, -gz·k)` |
| DEM 规则网格的近景纹理感 | 近景叠加两倍频 value noise 细节法线（远处自动关闭） |
| 远处法线走样 | 按视距衰减坡度（法线 LOD），配合大气透视 |

垂直夸张只作用在梯度上（`k`），所以几何位移与光照法线永远自洽，滑块可以实时拖动。

### 3. 重计算全在 GPU，主线程不做像素循环

- **AO 与梯度**由一次全屏离屏渲染产出（8 方位 × 4 半径的天空光遮蔽），主线程零百万像素循环
- 地形几何只存平面坐标，高度在顶点着色器里从纹理解析 —— 预构建时间与内存都大幅下降
- CPU 侧只保留拾取用的查表采样（65536 项 half→float 表，无逐像素转换）

### 4. 稳定 60 fps：分块 LOD + 帧预算

单一高密网格（1024² = 210 万三角面）在核显上只有个位数帧率。地形切成 **8×8 = 64 块**，
每块按屏幕尺寸在 **16 / 32 / 64 / 128** 四级细分之间切换，边缘加垂直裙边遮住接缝。
全景约 8–10 万三角面，贴地时自动升到 40–57 万。

额外措施：

- `FrameBudget` 用 p90/p10 抖动判据（不是绝对帧时间）决定是否降渲染分辨率——30 Hz 屏不会误判；
  且当 vsync 基线本身 > 25 ms 时直接不降档（降分辨率换不来帧率，只会白掉画质）
- 抗锯齿从 MSAA 4x 换成 FXAA 后处理：核显上 MSAA 会让地形着色成本近乎翻倍
  （贴地场景 6.65 → 12.38 ms），FXAA 只要约 0.5 ms
- 片元不设双三次 / 双线性的距离分支：核显上分支发散比多采样更贵
  （全双线性 13.0 ms vs 3000 m 阈值 21.6 ms），统一走硬件双线性，画质无可见损失
- 顶点采样按块分档：只有细分级别 ≥ 64 的块用 16-tap 双三次位移，远景块 1 次双线性
- 天空改为最后绘制 + 深度测试，被地形盖住的像素在 early-z 阶段直接剔除
- 天空着色器用平方 / 阈值代替 `pow`
- 相机静止时整段跳过 LOD 重算

### 5. 卫星影像（可选）：分块三档，按块从源图重采样

早先的做法是把整幅源图一次性降采样后再上传（14465² 源图 → 8192²，约 0.55 → 1 m/px），
近景永远是糊的。现在改成**分块 LOD**：

- 地形切成 **8×8 = 64 块**（1 km/块），每块绑定自己的卫星瓦片，三档按"块到相机的最近距离"实时切换
- 近景档由离线管线**直接从源图对应区域重采样**，不经过全图降采样；只要源图分辨率 ≥ 2048 px/km，
  近景档就等于源图原像素（当前示例源图 3998 × 3920 ≈ 2.0 m/px，近景档把源图放大到 0.49 m/px 输出，
  细节上限仍是源图的 2.0 m/px —— 换更高分辨率源图即可获得更清晰的近景）
- 为什么块粒度是 1 km 而不是更细：一个 drawcall 只能绑一张纹理，纹理块必须与几何块对齐；
  1 km 块用 2048² 已经对应 0.49 m/px，再细分只会增加显存与 drawcall，不会凭空增加源图没有的细节

**核显优化**（`src/terrain/satelliteLOD.js`）：

- 远景档全量常驻只有 **64 张 128² 纹理 ≈ 4 MB**，全景俯视时几乎不占显存
- 近景高清档有预算上限（「图形选项 → 近景高清块数」3 / 6 / 9 块），按距离择优，贴地飞行时也不会爆显存
- 每帧最多解码上传 1 张瓦片，用 `ImageBitmapLoader` 异步解码，不阻塞主线程
- 换档只替换纹理对象，几何、材质数量、drawcall 数完全不变
- LRU 淘汰：缓存超过 24 + 预算×4 条时释放最久未用的瓦片
- 瓦片统一 `flipY = false`，与高度纹理同为"首行 = 北"，影像不会上下颠倒

### 6. 日间薄雾与地形边界过渡

地形不是一块硬边方块：边缘 100–200 m 内平滑化入雾中，整体叠一层有方向的日间薄雾
（`hazeFactor` / `hazeTint`，地形与水面共用同一套函数）。

- **距离雾 + 高度衰减**：指数平方距离雾再乘 `mix(0.6, 1.0, exp(-y / 600))`——河谷、水面比山脊更朦胧，
  这是真实日间薄雾与"一层均匀灰膜"的区别
- **雾色带方向**：按 `s⁸`（Mie 前向散射近似）把雾色朝太阳色偏，逆光时雾本身发亮偏暖，顺光保持冷调
- **地形边界过渡**：`1 - smoothstep(100, 200, 到边界距离)`——距边界 100 m 内完全入雾，200 m 外完全清晰；
  边界处用纯环境雾色（与天空地平线同色），从外侧斜看也不会露出"方形底板"
- **水面同步**：GPU 浅水模拟的水面共用同一份 `uFogDensity` / `uFogColor` 与边界淡出，水体不会在边界处突然截断
- **天空对齐**：天空的地平线薄雾带也使用同一个 `uFogColor`，远处地形淡出成雾后与天空无缝衔接

### 7. 渲染设备：不做运行时切换

WebGL 既没有枚举显卡的 API，也没有运行时换 GPU 的 API。`src/viewer/gpuProbe.js` 只用来挑出
创建上下文时该给的 `powerPreference`：

1. **用两种 `powerPreference` 各开一个 WebGL2 上下文**，分别读 `WEBGL_debug_renderer_info`
   并比较 `MAX_TEXTURE_SIZE / MAX_SAMPLES / MAX_VERTEX_TEXTURE_IMAGE_UNITS`。双显卡机器上
   两者会落到不同 GPU，于是能"看见"两块设备；单卡或系统强制指定时会返回同一块——那也是真实情况。
   探测用的上下文用完立即 `WEBGL_lose_context` 释放。
2. **WebGPU 侧做同样的双偏好探测**（`navigator.gpu.requestAdapter` + `adapter.info`），只输出到控制台。

拿到设备列表后按"独显/集显定性关键词 + 硬件能力参数"打分，用最强一块对应的偏好创建主上下文。
`powerPreference` 只是给浏览器/驱动的建议，最终由系统决定，因此「图形选项」只显示上下文**实际**绑定的
GPU 名称，也不提供手动切换入口——不假装切换成功。

**上下文丢失要接住。** 浏览器出于省电（标签页不可见、切换电源方案）可能在上下文存活期间把显卡换掉
并丢弃上下文。所以监听了 `webglcontextlost`（`preventDefault` 否则不会恢复，面板提示等待恢复）与
`webglcontextrestored`（离屏预计算的 GPU 资源已被清空，必须重跑 `buildLookupTexture` 并刷新设备名）。
标签页重新可见时也会复核一次实际设备。

### 8. 地形编辑：实时位移 + 查询纹理节流重建

- 顶点着色器采样的是**原始高度图** `uHeight`（`heightField.texture`），不是打包后的查询纹理；
  笔刷每帧改完高度就 `texture.needsUpdate = true`，GPU 重新上传 R16F 数据，下一帧几何即变——
  不需要重建地形分块网格。
- AO / 梯度查询纹理（RGBA16F，光照与法线用）由 `createLookupUpdater` 复用同一个 render target
  原地重算：涂抹过程中约 **180 ms** 重建一次，笔画结束 / 撤销 / 恢复原始时立即重建。
  所以「高度即时、光影稍后」是设计取舍：位移不受重建延迟影响。
- 归一化高度（Float32Array）是编辑与导出用的 CPU 数据，写入时同步更新 half 位模式；
  「恢复原始」直接还原加载时保存的 originalHalf，逐字节精确。
- 导出时按 `terrain.json` 的 `sourceRange` 反算灰度，编码为 16-bit 灰度 PNG
  （`src/terrain/heightPng.js`，用 `CompressionStream('deflate')`，不依赖 canvas / 第三方库）。

16-bit / 8-bit 灰度 PNG 结构、CRC32、IHDR、zlib IDAT、与 `scripts/lib/png.mjs` 及 `sharp`
逐像素比对，并校验参数容错。**改 `src/terrain/heightPng.js` 后必须让它保持全绿。**

`tests/verify-merged.mjs` 是无第三方依赖的端到端验证脚本，通过 **headless Chrome + CDP**
（Node 全局 `WebSocket`，不需要 puppeteer）检查合并后的应用：

  192 张 `dist/data/sat/*.jpg`、`models/index.json`

## 部署（GitHub Pages）

仓库构建**一个前端**，产物 `dist/` 整体发布到 GitHub Pages 的站点根
（`https://zszqbgto.github.io/terrain/`）；不再有 `/modeldesigner/` 子路径，也没有第二个构建步骤。

### 持续集成与部署

`.github/workflows/deploy.yml`：

| 触发 | 行为 |
| --- | --- |
| push 到 `master` | `npm ci` → `npm run assets` → 校验资产 → `npm run build` → 校验产物 → 发布 `dist/` 到 GitHub Pages |
| Pull Request → `master` | 同上，但不发布（仅构建校验） |
| 手动 `workflow_dispatch` | 可按需手动发布一次 |

- **单项目、单 lockfile**：只安装根目录依赖（Node 22 + npm 缓存）
- **数据在 CI 里现场生成**：`public/data/` 不进仓库，构建阶段用 `npm run assets` 从
  `resourses/` 的源图生成；两张源图都已跟踪，因此 CI 能生成完整的 192 张卫星瓦片
  （若卫星源图缺失，管线会跳过瓦片，站点降级为高程分层，页面探测后不会报错）
- **显式产物校验**（缺一个即失败，避免发布一个没有地形的站点）：
  - 构建前：`public/data/height.f16`、`public/data/terrain.json`、`public/data/sat/` 下 192 张瓦片
  - 构建后：`dist/index.html`、`dist/data/height.f16`、`dist/data/terrain.json`、
    `dist/data/sat/0_0_128.jpg`、`dist/models/index.json`
- `npm run build` 的 `postbuild`（`node scripts/ensure-assets.mjs --dist`）会把缺失的 `dist/data`
  自动补齐，CI 的校验是发布前的最后一道关
- **首次启用需在仓库设置里指定来源**：Settings → Pages → Build and deployment → Source 选
  **GitHub Actions**（选 "Deploy from a branch" 不会用到本 workflow）
- `vite.config.js` 的 `base: './'` 让产物也能放在任意子路径下托管；官方站点地址为
  `https://zszqbgto.github.io/terrain/`

### 本地构建校验

```bash
npm run build           # 构建（postbuild 自动补齐 dist/data）
npm run preview         # 本地预览 dist/（预览服务器没有模型写入接口）
```

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面停在"读取高程数据…"或提示加载失败 | `public/data/height.f16` 或 `terrain.json` 不存在 → 重新启动 `npm run dev`（自动守卫会补齐），或手动 `npm run assets` |
| `npm run dev` 启动很慢、日志停在"正在执行资产管线" | 首次生成卫星瓦片要把源图（≈1570 万像素）解码一次，本机约 20 秒（更慢的机器可能数分钟）；等它完成，或临时用 `npm run assets -- --height-only` 只生成高度场 |
| 面板没有卫星影像 / 贴图不影响地形 | 正常降级：`public/data/sat/` 不存在。把卫星源图放进 `resourses/` 后重启 dev（或 `npm run assets`） |
| 控制台出现 `sat/0_0_128.jpg` 404 | 卫星可用性探针的预期结果，不影响地形显示 |
| 卫星影像模糊 | 近景高清块数用尽或显存不足；调高"近景高清块数"，或靠近后等待瓦片异步加载 |
| 帧率偏低 | 已由 `FrameBudget` 自动降渲染分辨率；也可降低"近景高清块数"、关闭水面 |
| 构建后 `dist/data` 里没有瓦片 | `postbuild` 会自动补齐；也可手动 `node scripts/ensure-assets.mjs --dist` |
| 导入模型刷新后丢失 | 静态托管下导入的模型只存在浏览器 IndexedDB（换浏览器/清缓存会丢），用「⇥ 移入 public/models」或「⭳ 下载文件」后放进 `public/models/` |
| 网页导入模型没有写进 `public/models/` | 写盘依赖 dev server 的 `/__models/*` 接口；`npm run preview` 与生产托管没有这些接口 |
| 标签不显示 | 「图形选项 → 标签显示」被关掉；或游览模式会临时隐藏标签 |
| 相机钻进地形 / 飞出土地方形 | 「图形选项 → 碰撞」被关掉；打开即恢复贴地与边界限制 |
| 水体没有出现 | 「图形选项 → 水面」关闭、模拟被暂停，或没有放置水源；水体编辑模式放一个「＋水源」试试 |
| 地形编辑涂抹没反应 | 确认处于「地形编辑」模式且点在**地形范围内**（画布为十字准星，鼠标处应有浅蓝色指示圈）；涂抹用左键，滚轮 / 中键 / 右键仍是视角操作；`Esc` 结束当前笔画 |
| 地形编辑刷新后丢失 | 编辑存在浏览器 IndexedDB（换浏览器 / 清缓存会丢）；要长期保存请导出灰度图并替换 `resourses/heightmap64.png` 后重建资产 |
| 地形编辑后水体 / 模型位置没变 | 两者都读同一份高度图：水面会按新地形重新扩散（必要时「重置模拟」），模型用「贴地」重新落位 |
| 导出的灰度图怎么用 | 重命名为 `heightmap64.png` 放进 `resourses/`，执行 `npm run assets`（或重新 `npm run dev` 触发自动守卫）重建 `height.f16` 与卫星瓦片 |
| 想换区域 | 替换 `resourses/heightmap64.png`（16 bit 灰度）并修改 `terrain.json` 的 `sizeMeters` 与 `elevation` 后重跑 `npm run assets` |

## 已知限制

- `.gltf`（文本）若引用外部 `.bin`/贴图，单独导入会缺资源 —— 请优先用单文件 `.glb`
- 静态托管下导入的模型只存在浏览器里（换浏览器/清缓存会丢），请用「⇥ 移入 public/models」或「⭳ 下载文件」后放进 `public/models/`
- 资源文件夹的写入依赖 dev server 的 `/__models/*` 接口；`npm run preview` 与生产托管没有这些接口
- 单模型上限 256 MB；文件名不允许路径分隔符与 `: * ? " < > |`（会被拒绝）
- 水面是模拟网格的近似：模拟分辨率 256–1024 对应约 31–7.8 m/格，极窄沟渠 / 细小结构可能被平均掉
- 水面高度由模拟决定，不能再直接「输入一个水面高度值」；「目标水面高程」只限制该水源注到哪，不是强制水位
- 多水源共享一个全局水位上限（取所有启用且有目标水位的水源里的最高值；任一不限则不设上限）
- 水体模拟需要 WebGL2 + 浮点颜色缓冲，且模拟分辨率越高越吃 GPU / 显存（768 时 4 个模拟缓冲各约 9 MB）
- 不导出 glb：编辑结果（缩放/旋转/部件微调）只存在于工程 JSON，没有把变换烘回模型文件
- 不导出图片 / 缩略图；不保存当前水位（导入后从干地重新模拟）
- 地形高度编辑不写入工程 JSON（单独存浏览器 IndexedDB），分享 / 换机需导出 16-bit 灰度 PNG 并重建资产
- 浏览器里看到的是编辑后的地形；`public/data`（`height.f16` / 卫星瓦片）仍由原源图生成，直到按导出流程重建
- 地形编辑只有撤销（最多 8 步，无重做），没有笔刷遮罩 / 图层 / 撤销历史持久化；导出的是灰度 DEM 源图，不是 glTF / OBJ 网格
- 水体模拟在编辑后的地形上继续运行：地形变高可能淹没 / 露出水源，必要时「重置模拟」重新注水
- 标签不驱动任何逻辑（只是名称 + 类型 + 挂载点，不做动画/条件/业务联动）
- 暂无撤销/重做、多选、对齐吸附；无服务器端存储（纯前端，数据在本机）
- 卫星瓦片依赖 `resourses/` 的卫星源图；源图缺失时站点只能展示高程分层地形（功能不受影响）
