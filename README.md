# 尚庄炉水库 · 8 km 三维地形浏览器

基于 **Three.js + Vite** 的离线三维地形浏览器。把 8 km × 8 km 的 DEM 高程图渲染成可自由浏览的地形：
高程位移、法线、环境光遮蔽、分层着色与等高线全部在 GPU 上计算，主线程不做任何像素循环。

以尚庄炉水库（山东）为示例数据，换一份 DEM 即可复用于其他区域。

- **高程分层着色**：13 色标高程色带（hypsometric tint）+ 矢量等高线（屏幕导数自适应线宽），分层数可调 6–48
- **卫星影像（可选）**：分块三档 LOD，近景 0.49 m/px，直接取回源图原像素
- **分块几何 LOD**：8×8 块 × 4 级细分，核显也能稳定 60 fps
- **日间薄雾**：距离雾 × 高度衰减 × 太阳前向散射，地形边界 100–200 m 雾化过渡
- **零运行时依赖后端**：静态资源 + 离线资产管线，`npm run build` 后可直接托管

## 快速开始

### 环境要求

| 依赖 | 版本 / 说明 |
| --- | --- |
| Node.js | ≥ 20.19（Vite 7 的要求） |
| 浏览器 | 支持 WebGL2；集显即可运行 |
| sharp | `devDependency`，仅离线资产管线使用，运行时不需要 |

### 安装与运行

```bash
npm install      # 安装依赖（three / vite / sharp）
npm run assets   # 生成 public/data 下的运行时资产（缺源图的部分自动跳过）
npm run dev      # 开发服务器 http://127.0.0.1:5173
```

源数据放在 `resourses/`（或仓库根目录）后再执行 `npm run assets`，详见[数据准备](#数据准备)。

| 命令 | 作用 |
| --- | --- |

| `npm run build` | 生产构建到 `dist/`（`base: './'`，可放在任意子路径下托管） |

## 数据准备

### 源数据

| 文件 | 必需 | 格式 |
| --- | --- | --- |
| `heightmap64.png` | **是** | 1081 × 1081，16 bit 灰度 DEM（单通道） |
| `尚庄炉水库卫星影像64.png` | 否 | 14465 × 14178 卫星影像（PNG，含 alpha 时会自动铺底） |

两个文件都会被在 `resourses/` 与仓库根目录两处查找。

### 资产管线行为

`npm run assets` 把两类源数据当作**各自独立的任务**：

- `heightmap64.png` 缺失 → 跳过高度场，打印提示，继续尝试卫星瓦片
- 卫星影像缺失 → 跳过瓦片生成并明确说明"运行时不提供卫星影像"
- 两者都缺 → 仍然以退出码 0 结束（只提示去放源数据），不制造无意义的失败
- `--height-only` → 显式只做高度场

产物写入 `public/data/`（该目录已加入 `.gitignore`，可由管线随时重建）：

```
public/data/
├── height.f16      # half-float 归一化高度，2.2 MB（1081²，GPU 零转换上传）
├── terrain.json    # 元数据：尺寸、地形边长、块数、高程区间
└── sat/            # 卫星瓦片（可选）
    └── {cx}_{cz}_{2048|512|128}.jpg   # 8×8 块 × 3 档 = 192 张
```

耗时参考：高度场约 2 秒；卫星瓦片需把 365 MB / 2 亿像素的源图解码一次，再逐块重采样
（一次解码而非逐块解码，否则要跑十几分钟），总时长取决于源图尺寸与磁盘速度。

### 运行时降级

页面启动时会用一张远景瓦片（`sat/0_0_128.jpg`）探测卫星影像是否存在：

- 存在 → 创建瓦片调度器，面板出现「高程分层 / 卫星影像」切换与「近景高清块数」
- 不存在 → 不创建调度器，**默认且只能展示高程分层地形**，面板不出现卫星相关控件

因此没有卫星图是完全正常的运行状态，不是错误。

### `terrain.json` 字段

| 字段 | 说明 |
| --- | --- |
| `width` / `height` | 高度图像素尺寸 |
| `sizeMeters` | 地形实际边长（默认 8000 m） |
| `chunkCount` | 几何/瓦片分块数（默认 8，即每块 1 km） |
| `elevation.minMeters` / `maxMeters` | 高程区间，默认 55–310 m |
| `sourceRange` | 源图灰度极值与位深，仅作记录 |

> 源图不含地理元数据，高程区间是按该区域地形的估计值。可直接改 `terrain.json`；
> 垂直夸张只影响观感，不影响"光标高程"的读数换算。

## 技术文档

### 架构与数据流

```
heightmap64.png ──(Node: 16bit 解码 + half 归一化)──► public/data/height.f16 (2.2 MB)
                                                          │
                                                DataTexture(R16F)  零转换上传
                                                          │
                              ┌───────────────────────────┴───────────────────────────┐
                     离屏 pass（gpuLookup.js）                            顶点着色器
          R=高度 G=AO B=∂h/∂x A=∂h/∂z  (RGBA16F 查询纹理)        高度 = 纹理采样位移
                              │                                                       │
                     片元着色器：法线 / 光照 / 分层 / 等高线 / 日间薄雾 ◄──────────────┘
```

- 几何只存平面坐标（x/z + uv），高程全部由顶点着色器从查询纹理解析
- 运行时只有静态资源，没有服务端逻辑；`build` 产物可放在任意静态托管

### 1. 高程分层着色（算出来的，不是贴图）

- 色带是 512×1 的 LUT 纹理，色标定义在 `src/terrain/palette.js`
- 分层用 `floor(h * bands)` 量化，层内保留少量连续渐变，避免色阶把起伏吃掉
- **等高线用 `fwidth(h * bands)` 换算线宽**：线宽随屏幕导数自适应，任何距离、任何倾角都保持约 1 px，不会闪成麻点

### 2. 消除"像素方块感"

方块感通常来自五处，这里逐一消除：

| 来源 | 处理 |
| --- | --- |
| 8 bit 量化台阶 | 源图 16 bit 直接转 half-float 上传，不经 canvas（canvas 只能给 8 bit） |
| 最近邻 / 双线性采样的菱格 | 片元与顶点都用 4×4 = 16 tap 的 **Catmull-Rom 双三次采样** |
| 低面数网格的平面着色 | 法线不来自几何，而是由高度场梯度矢量解析：`n = normalize(-gx·k, 1, -gz·k)` |
| DEM 规则网格的近景纹理感 | 近景叠加两倍频 value noise 细节法线（远处自动关闭） |
| 远处法线走样 | 按视距衰减坡度（法线 LOD），配合大气透视 |

垂直夸张只作用在梯度上（`k`），所以几何位移与光照法线永远自洽，滑块可以实时拖动。

### 3. 重计算全在 GPU，主线程不做像素循环

- **AO 与梯度**由一次全屏离屏渲染产出（8 方位 × 4 半径的天空光遮蔽），主线程零百万像素循环
- 地形几何只存平面坐标，高度在顶点着色器里从纹理解析 —— 预构建时间与内存都大幅下降
- CPU 侧只保留拾取用的查表采样（65536 项 half→float 表，无逐像素转换）

### 4. 稳定 60 fps：分块 LOD + 帧预算

单一高密网格（1024² = 210 万三角面）在核显上只有个位数帧率。地形切成 **8×8 = 64 块**，
每块按屏幕尺寸在 **16 / 32 / 64 / 128** 四级细分之间切换，边缘加垂直裙边遮住接缝。
全景约 8–10 万三角面，贴地时自动升到 40–57 万。

额外措施：

- `FrameBudget` 用 p90/p10 抖动判据（不是绝对帧时间）决定是否降渲染分辨率——30 Hz 屏不会误判；
  且当 vsync 基线本身 > 25 ms 时直接不降档（降分辨率换不来帧率，只会白掉画质）
- 抗锯齿从 MSAA 4x 换成 FXAA 后处理：核显上 MSAA 会让地形着色成本近乎翻倍
  （贴地场景 6.65 → 12.38 ms），FXAA 只要约 0.5 ms
- 片元不设双三次 / 双线性的距离分支：核显上分支发散比多采样更贵
  （全双线性 13.0 ms vs 3000 m 阈值 21.6 ms），统一走硬件双线性，画质无可见损失
- 顶点采样按块分档：只有细分级别 ≥ 64 的块用 16-tap 双三次位移，远景块 1 次双线性
- 天空改为最后绘制 + 深度测试，被地形盖住的像素在 early-z 阶段直接剔除
- 天空着色器用平方 / 阈值代替 `pow`
- 相机静止时整段跳过 LOD 重算

### 5. 卫星影像（可选）：分块三档，近景直接取回原像素

早先的做法是把 14465² 源图整幅降到 8192² 再上传，等于把 0.55 m/px 压成 1 m/px —— 近景永远是糊的。
现在改成**分块 LOD**：

- 地形切成 **8×8 = 64 块**（1 km/块），每块绑定自己的卫星瓦片，三档按"块到相机的最近距离"实时切换
- 近景档由离线管线**直接从源图对应区域重采样**，不经过全图降采样，细节是源图原生水平
- 为什么块粒度是 1 km 而不是更细：一个 drawcall 只能绑一张纹理，纹理块必须与几何块对齐；
  而清晰度上限由源图 0.55 m/px 决定，1 km 块用 2048² 已经是 0.49 m/px，再细分不会更清晰

**核显优化**（`src/terrain/satelliteLOD.js`）：

- 远景档全量常驻只有 **64 × 85 KB ≈ 5 MB**，全景俯视时几乎不占显存
- 近景高清档有预算上限（面板可选 3 / 6 / 9 块），按距离择优，贴地飞行时也不会爆显存
- 每帧最多解码上传 1 张瓦片，用 `ImageBitmapLoader` 异步解码，不阻塞主线程
- 换档只替换纹理对象，几何、材质数量、drawcall 数完全不变
- LRU 淘汰：缓存超过 24 + 预算×4 条时释放最久未用的瓦片
- 瓦片统一 `flipY = false`，与高度纹理同为"首行 = 北"，影像不会上下颠倒

### 6. 日间薄雾与地形边界过渡

地形不是一块硬边方块：边缘 100–200 m 内平滑化入雾中，整体叠一层有方向的日间薄雾
（`hazeFactor` / `hazeTint`，地形与水面共用同一套函数）。

- **距离雾 + 高度衰减**：指数平方距离雾再乘 `mix(0.6, 1.0, exp(-y / 600))`——河谷、水面比山脊更朦胧，
  这是真实日间薄雾与"一层均匀灰膜"的区别
- **雾色带方向**：按 `s⁸`（Mie 前向散射近似）把雾色朝太阳色偏，逆光时雾本身发亮偏暖，顺光保持冷调
- **地形边界过渡**：`1 - smoothstep(100, 200, 到边界距离)`——距边界 100 m 内完全入雾，200 m 外完全清晰；
  边界处用纯环境雾色（与天空地平线同色），从外侧斜看也不会露出"方形底板"
- **水面同步**：同一套雾色 + 边界处 alpha 淡出到 0，水体不会在边界处突然截断
- **天空对齐**：天空的地平线薄雾带也使用同一个 `uFogColor`，远处地形淡出成雾后与天空无缝衔接

### 7. 渲染设备：不做运行时切换

WebGL 既没有枚举显卡的 API，也没有运行时换 GPU 的 API。`src/viewer/gpuProbe.js` 只用来挑出
创建上下文时该给的 `powerPreference`：

1. **用两种 `powerPreference` 各开一个 WebGL2 上下文**，分别读 `WEBGL_debug_renderer_info`
   并比较 `MAX_TEXTURE_SIZE / MAX_SAMPLES / MAX_VERTEX_TEXTURE_IMAGE_UNITS`。双显卡机器上
   两者会落到不同 GPU，于是能"看见"两块设备；单卡或系统强制指定时会返回同一块——那也是真实情况。
   探测用的上下文用完立即 `WEBGL_lose_context` 释放。
2. **WebGPU 侧做同样的双偏好探测**（`navigator.gpu.requestAdapter` + `adapter.info`），只输出到控制台。

拿到设备列表后按"独显/集显定性关键词 + 硬件能力参数"打分，用最强一块对应的偏好创建主上下文。
`powerPreference` 只是给浏览器/驱动的建议，最终由系统决定，因此面板只显示上下文**实际**绑定的 GPU，
也不提供手动切换入口——不假装切换成功。

**上下文丢失要接住。** 浏览器出于省电（标签页不可见、切换电源方案）可能在上下文存活期间把显卡换掉
并丢弃上下文。所以监听了 `webglcontextlost`（`preventDefault` 否则不会恢复，面板提示等待恢复）与
`webglcontextrestored`（离屏预计算的 GPU 资源已被清空，必须重跑 `buildLookupTexture` 并刷新设备名）。
标签页重新可见时也会复核一次实际设备。

### 性能实测

## 项目结构

```
index.html                  页面、HUD 样式、加载遮罩
src/main.js                 装配：加载 → GPU 预计算 → LOD → 渲染循环
src/terrain/
  heightfield.js            height.f16 → R16F 纹理 + CPU 拾取采样器
  gpuLookup.js              离屏 pass：梯度 + 天空光遮蔽 → RGBA16F 查询纹理
  terrain.js                分块 LOD 网格 + 高程分层材质 + 每块卫星材质 + 环境 uniform
  satelliteLOD.js           卫星瓦片调度（三档 / 预算 / 异步解码 / LRU）+ 可用性探针
  shaders.js                顶点位移、分层着色、等高线、日间薄雾、天空、水面
  palette.js                高程色带 LUT
  environment.js            天空球与水面
src/viewer/
  controls.js               轨道 + 飞行 + 拾取
  framebudget.js            自适应渲染分辨率
  fxaa.js                   FXAA 后处理（替代 MSAA）
  gpuProbe.js               渲染设备探测（双 powerPreference + WebGPU adapter）
  hud.js                    HUD 与参数面板（按卫星可用性裁剪控件）
scripts/
  prepare-assets.mjs        离线资产管线（PNG 解码 / 分块切瓦片 / half float；缺源图自动跳过）
  lib/png.mjs               流式 PNG 解码器（8/16 bit，灰度/RGB/RGBA）
resourses/                  源数据（git 忽略二进制大图时请自行准备）
public/data/                资产管线产物（git 忽略，可随时重建）
```

## 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 页面停在"读取高程数据…"或提示加载失败 | `public/data/height.f16` 或 `terrain.json` 不存在 → 放好 `heightmap64.png` 后执行 `npm run assets` |
| 面板没有"卫星影像"按钮 | 正常降级：`public/data/sat/` 不存在。要卫星模式就补充卫星源图并重跑 `npm run assets` |
| 控制台出现 `sat/0_0_128.jpg` 404 | 同上，是卫星可用性探针的预期结果，不影响地形显示 |
| 卫星影像模糊 | 近景高清块数用尽或显存不足；调高"近景高清块数"，或靠近后等待瓦片异步加载 |
| 帧率偏低 | 已由 `FrameBudget` 自动降渲染分辨率；也可降低"近景高清块数"、关闭水面 |
| 想换区域 | 替换 `heightmap64.png`（16 bit 灰度）并修改 `terrain.json` 的 `sizeMeters` 与 `elevation` |
