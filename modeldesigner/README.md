# 地形模型编辑（terrain · modeldesigner）

在 **8 km DEM 三维地形**上做模型沙盘：导入多个 `.glb`、实时调整位置/旋转/缩放、复制摆放、
给模型或 glb 部件打标签（动态结构 / 静态标注），并在地形上点选放置水源、用 **GPU 浅水模拟**
生成会流动、会漫溢的水面，最后把整个场景导出成工程 JSON。

地形渲染（分块 LOD、高程分层、日间薄雾、FXAA）复用自兄弟项目 `../terrain`，
**复制**了一份到 `src/terrain`、`src/viewer`，因此本项目可独立运行、不依赖父目录。
水体模拟移植自 `D:\Proj\test\pilo.js` 的 GPU 浅水流体，按本项目的 three.js 地形渲染方式适配。

## 快速开始

```bash
cd modeldesigner
npm install
npm run dev        # http://127.0.0.1:5174
```

地形数据（`public/data/height.f16`、`terrain.json`）已随项目就绪；要换成别的区域，
把 16bit 灰度 DEM 放到 `resourses/heightmap64.png` 后执行 `npm run assets`。

## 模型从哪来

三种方式，最终都会汇入同一个**资源文件夹** `public/models/`：

| 方式 | 行为 |
| --- | --- |
| 把 `.glb` 直接放进 `public/models/` | 刷新页面即出现在左侧「资源库」（dev 下是实时目录扫描） |
| 网页「导入模型」或把文件拖进窗口 | dev server 会把它**写回 `public/models/`**（`POST /__models/upload`），同时放进场景 |
| 静态托管（`npm run build` 产物）导入 | 没有写盘能力，glb 暂存到浏览器 IndexedDB，界面上可「⇥ 移入文件夹」或「⭳ 下载」后自行放入 |

左侧「资源库」**始终显示资源文件夹里的内容**，其次是浏览器里暂存的资源（标注为「本地」）。

试试生成一个示例模型（底座 + 塔身 + 转臂，便于演示部件标签）：

```bash
npm run models:sample     # 生成 public/models/sample-tower.glb
```

## 地形贴图（可选）

地形贴图是**分块卫星瓦片 LOD**（与父项目 `terrain` 同一套实现）：8×8 = 64 块，
每块按「块到相机的最近距离」在三档之间切换：

| 档位 | 纹理 | 触发距离 | 显存/块 |
| --- | --- | --- | --- |
| 近景 | 2048² | < 1400 m | ≈21 MB |
| 中景 | 512² | 1400–3400 m | ≈1.3 MB |
| 远景 | 128² | > 3400 m | ≈85 KB |

**生成瓦片**：把卫星影像放到 `resourses/尚庄炉水库卫星影像64.png`，然后

```bash
npm run assets
```

会写出 `public/data/sat/{cx}_{cz}_{2048|512|128}.jpg`（192 张）并更新 `terrain.json`。
没有瓦片时地形自动回退到高程分层着色（启动时用一张远景瓦片探测目录是否存在），
功能不受影响。

## 全局贴图开关

工具栏的「贴图：开 / 关」同时控制两侧：

| 对象 | 开 | 关 |
| --- | --- | --- |
| 地形 | 卫星瓦片铺贴（需已生成瓦片） | 高程分层着色 |
| 模型 | 显示 glb 自带的贴图（`map`） | 材质摘掉 `map`，回退纯色 PBR |

开关状态存在 `localStorage`（`modeldesigner.settings.v1`），刷新后保持；
没有卫星瓦片时按钮仍可用（只影响模型贴图），tooltip 会注明当前地形没有贴图。

### 水体编辑模式

顶栏「水体编辑」切到水体模式（与「模型编辑」互斥，共用同一套两列栅格）。左右面板与模型模式对称：

| 位置 | 内容 |
| --- | --- |
| 左「水体模拟」 | ＋水源 / 清空 + 水源列表（名称、地面高程、半径、启用、删除） |

5. 水源标记只在水体编辑模式显示；切回模型模式会自动隐藏并结束放置

### 薄雾强度

「图形选项 ▾ → 薄雾强度」滑杆（0–3×，默认 1.0×）一次调节三方：

| 对象 | 用的是什么 |
| --- | --- |
| 地形 | 自定义日间雾 `env.uFogDensity`（按高度衰减的 haze） |
| 水体（模拟水面） | 直接引用同一份 `env.uFogDensity`，拖动即为所见 |
| 模型 | three 的 `scene.fog`（FogExp2），密度同步调整 |

## 水体模拟

水体改为移植自 `D:\Proj\test\pilo.js` 的 **GPU 浅水模拟**（three.js 适配版），
旧的「水面区域 / 流动水」模块已整体删除。

实现位于 `src/water/`：`fluidWater.js`（模拟主类：模拟域 / 水源 / 参数 / 序列化）、
`waterShaders`（4 个 ping-pong pass + 水面网格着色）、`waterTextures`（程序化法线 / 泡沫纹理）、
`waterState.js`（schema 默认值与归一化，工程与运行时共用）。

### 模拟域：自动覆盖整个地形

- 模拟域**自动覆盖整个 8 km 地形**（`heightField.sizeMeters`），高程直接取现有的
  `heightField.texture` —— 与地形顶点着色器用的是同一份 DEM（R16F 归一化高程），
  所以**没有「创建高度图 / 手动调模拟范围」这一步**（这是和 `D:\Proj\test` 里 Cesium 流程最大的不同）
- 直接在地形上点选放置水源即可开始注水，水面自己按地形起伏扩散、漫溢、蓄积
- 模拟在 256–1024 的 GPU 纹理上跑；渲染用的水面网格是覆盖全域的一张平面网格，
  顶点按模拟水位位移，两者解耦

### 模拟怎么跑（4 个 ping-pong pass）

每个**子步**依次跑 4 个全屏 pass（与 `pilo.js` 原实现的缓冲读写顺序一致）：

| pass | 写什么 | 读什么 |
| --- | --- | --- |
| A | 地形高度 + 水深（含水源注水） | C、D |
| B | 4 向流出量（第 1 段） | A、D |
| C | 地形高度 + 水深（第 2 段） | A、B |
| D | 4 向流出量（第 2 段） | C、B |

- 4 个模拟缓冲都是浮点颜色纹理（正常为 RGBA32F；GPU 不支持浮点颜色缓冲时自动退到半浮点，精度略低但可用）
- 水源注水按固定节拍（每 2 个子步注入一次），注到目标水位就停
- 每帧的子步数由「模拟速度」控制：0.1–4 倍，1× = 60 Hz 下每帧 1 个子步；单帧最多推进 4 步，
  掉帧后不会一次补跑太多
- **模拟域边界当作封闭的墙**：朝地形外侧的流量记 0，邻居采样也不跨出边界 —— 水既不会从边界漏光，
  也不会因为边界重复计数而“凭空变多”（早期版本就是这里导致停用注水后水体总量还在增长）
- **全局水位上限** = 所有**启用**且设置了目标水位的水源里的**最高目标水位**；只要有任一启用水源
  是「不限制」，就**没有**上限。超出上限的水被直接排掉（相当于溢洪道），
  所以多个水源也不会把整张地图无限灌高

### 面板参数

**模拟参数**：

| 参数 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 模拟速度 | 0.1–4× | 1× | 1× = 60 Hz 下每帧 1 个子步 |
| 每次注水量 | 1–300 米 | 15 米 | 每个水源每次注水按这个水深注入 |
| 模拟精度 | 256 / 512 / 768 / 1024 | 768 | 模拟网格边长；切换会重建模拟缓冲，水位归零重新模拟 |
| 暂停 / 继续 | — | 运行中 | 暂停时不再推进模拟，但仍显示当前水面 |
| 重置模拟 | — | — | 水位与流量全部清零，从干地重新开始 |

**选中水源**：

| 参数 | 范围 / 默认 | 说明 |
| --- | --- | --- |
| 名称 | 默认「水源 N」 | 也显示在场景的 CSS2D 名称里 |
| 地面高程 | 只读 | 按水源位置自动采样；新水源的目标水位默认 = 该值 + 10 m |
| 水源半径 | 20–2000 米（默认 150） | 注水范围；场景圆环按此半径贴地绘制 |
| 目标水面高程 | 米；0 或留空 = 不限制 | 该水源注到这一高程就停；新水源默认 = 地面 + 10 m |
| 启用 | 默认开 | 停用的水源不注水，也不参与全局水位上限 |
| 删除 | — | 只删这个水源，已经流进模拟里的水会留下 |

**外观**：

| 参数 | 范围 | 默认 |
| --- | --- | --- |
| 太阳高光 | 0–3 | 1.0 |
| 波纹强度 | 0–2 | 1.0 |
| 水体清澈度 | 0–1 | 0.62（0 浑浊、1 通透） |

> 最多 **8 个水源**；「清空」删除全部水源；「保存」立即写入本地工程。
> 面板底部状态行显示**模拟步数 · 水源数**（暂停时标「已暂停」）；湿格数与最深值来自
> `debugStats()` 的 GPU 读回，供调试/自动化使用。

### 水面渲染

一张覆盖全域的网格（默认 **512×512 段**）按模拟水位在顶点着色器里位移；片元里：

- 用模拟水位求几何法线，再叠两层**程序化法线贴图**（可平铺、带 mipmap + 各向异性过滤，
  沿净流速方向平流）—— 近处细碎、远处不闪
- **Schlick 菲涅尔**：正视看水体色，掠视几乎全是天空反射；反射色与天空着色器同色
- **太阳高光**：锐利太阳镜面 + 较宽泛光 + 掠射角细碎波光（由「太阳高光」控制）
- **深度吸收（Beer-Lambert 近似）**：浅水透出水下地形色，深水接近不透明；
  「水体清澈度」控制吸收强弱
- **泡沫**：岸边拍岸细碎泡沫 + 急流白浪（由净流速与水深驱动）
- 与地形**完全一致的日间薄雾**和地形边界淡出：水面在边界处淡出到透明，不会露出方形硬边

「图形选项 ▾ → 水面：开 / 关」是水体总开关，关闭后不渲染、也不推进模拟（状态存 `localStorage`）。

### 精度与性能

- 模拟分辨率决定模拟网格的物理大小：8 km ÷ 256 ≈ 31 m/格，512 ≈ 15.6 m/格，
  768 ≈ 10.4 m/格，1024 ≈ 7.8 m/格
- 768 时 4 个 RGBA32F 模拟缓冲各约 9 MB（另有一张同分辨率的合成纹理）；
  256/512 更快更省显存，1024 最细但 GPU 开销最大
- 需要 **WebGL2 + 浮点颜色缓冲**（`EXT_color_buffer_float`）；没有时自动退半浮点

### 持久化

- 水体数据写入工程 JSON 的 `water` 字段：`{ enabled, sim, visual, sources[] }`
  （逐字段说明见 [docs/EXPORT-FORMAT.md](docs/EXPORT-FORMAT.md)）
- 水源与参数变化走工程自动保存（400 ms 防抖），也可点面板「保存」立即落盘
- 恢复工程时按保存的**水源与参数重新开始模拟**：不保存当前水位，水面从干地重新注水
- 旧工程的 `areas` / `flows` **不迁移**，归一化后 `sources` 为空

### 相机碰撞

工具栏「碰撞：开 / 关」控制相机是否被地形挡住：

- **开**（默认）：不会钻进地形（按最小离地高度贴地），也不会飞出地形方形边界
- **关**：自由穿行 —— 可以钻到地形以下、飞出土地方形范围，方便检查地下/边界效果

状态存在 `localStorage`（`modeldesigner.settings.v1` 的 `cameraCollision`），刷新后保持。

### 编辑

检查器自上而下是：**部件 → 名称 → 变换 → 标签 → 模型**。
所有编辑都跟随「当前选择」——而选择只有两种来源：

| 操作 | 功能 |
| --- | --- |
| 在**部件栏**点「整个模型」/ 某个部件 | 决定下面「名称 / 变换 / 标签」作用于谁 |
| 左键点场景里的物体 | 只选中**整个模型**（不会选中部件） |
| `1` / `2` / `3` | 切换 gizmo：移动 / 旋转 / 缩放 |
| 拖 gizmo | 实时变换当前选择，检查器的 P/R/S 数值同步刷新（拖动期间自动禁用相机，避免带转视角） |
| 检查器数值框 | 精确输入位置（米）/ 旋转（度）/ 缩放（倍率）；每轴带 X/Y/Z 标记，颜色与 gizmo 轴一致（X 红 / Y 绿 / Z 蓝） |
| 名称输入框 | 改当前选择的名称：整体改模型名，部件改该节点名（写进工程） |
| 「贴地」 | 把模型包围盒最低点落回地表（作用于整个模型） |
| 「删除模型」 / `Delete` | 删除整个模型 |
| `Ctrl+D` / 列表里的 ⧉ | 深拷贝一份（含标签与部件变换），偏移 60 m 放置 |
| `Esc` | 取消选择 |

> 没有「编辑模型 / 编辑部件」这类开关：点部件栏里的谁，就编辑谁。

### 标签

标签挂在**当前选择**上，列表也只显示当前范围的标签：

1. 在部件栏点「整个模型」或某个部件
2. 在名称框里填**标签名称**（留空则用模型名 / 部件名），点「+ 添加」
3. 新标签**默认为「静态标注」**（琥珀色胶囊），需要时在标签卡上点
   「动态结构」（青色）切换类型，之后可随时改
4. 名字和类型都可以随时改；类型只是给这个标签定性，不附带别的作用

> 也就是说：**创建时只管名字，默认静态标注，类型随时可改**；标签只属于它挂的那个对象。

## 工程与持久化

- **自动保存**：任何编辑 400 ms 后写入 `localStorage`（工程结构与 glb 分离；水源与水体参数也在工程里）
- **刷新恢复**：glb 从 `public/models/` 或 IndexedDB 重新读取，变换与标签全部还原；
  水体按保存的水源与模拟参数重新开始注水（不保存当前水位）
- **导出工程**：`导出工程` 按钮 →
  - 确定 = **内嵌 glb**（单文件，可跨机器，体积大）
  - 取消 = **只导出引用**（依赖 `public/models/` 里的文件）
- **导入工程**：会替换当前场景；内嵌模式会自动把 glb 写回资源文件夹
- **清空场景**：只清实例、水体与本地工程，不动资源文件夹

导出 JSON 的逐字段说明（坐标约定、单位、索引路径、标签结构）见
**[docs/EXPORT-FORMAT.md](docs/EXPORT-FORMAT.md)**。

- 部件级编辑：部件栏选择 + 部件局部变换与改名（都会写进工程）

## 已知限制

- `.gltf`（文本）若引用外部 `.bin`/贴图，单独导入会缺资源 —— 请优先用单文件 `.glb`
- 静态托管下导入的模型只存在浏览器里（换浏览器/清缓存会丢），请用「移入文件夹」或下载后放进 `public/models/`
- 资源文件夹的写入依赖 dev server 的 `/__models/*` 接口；`npm run preview` 与生产托管没有这些接口
- 单模型上限 256 MB；文件名不允许路径分隔符与 `: * ? " < > |`（会被拒绝）
- 水面是模拟网格的近似：模拟分辨率 256–1024 对应约 31–7.8 m/格，极窄沟渠 / 细小结构可能被平均掉
- 水面高度由模拟决定，不能再直接「输入一个水面高度值」；「目标水面高程」只限制该水源注到哪，不是强制水位
- 多水源共享一个全局水位上限（取所有启用且有目标水位的水源里的最高值；任一不限则不设上限）
- 水体模拟需要 WebGL2 + 浮点颜色缓冲，且模拟分辨率越高越吃 GPU / 显存（768 时 4 个模拟缓冲各约 9 MB）
